# QUIK Server Monitor

Простой Telegram-бот: каждые 30 секунд проверяет, работают ли нужные службы Windows на сервере QUIK
(на этом же компьютере или на другом сервере по сети),
и пишет админу, если служба остановилась и когда она снова заработала.

Список служб админ ведёт сам прямо в Telegram, без правки файлов и перезапуска.

Бот только читает состояние служб (`sc query`), ничего не запускает и не останавливает.

## Команды бота

| Команда | Что делает |
|---|---|
| `/status` | состояние всех отслеживаемых служб |
| `/find quik` | найти службу на сервере по части имени |
| `/add QuikServerQ QUIK Server` | добавить службу (имя + необязательное название) |
| `/remove QuikServerQ` | убрать службу из списка |
| `/help` | справка |

**Имя** — короткое имя службы Windows (Name), а не отображаемое. Если не знаете его — `/find`.

Уведомления:
- 🔴 **Служба не работает** — служба не в состоянии «работает» две проверки подряд;
- 🟢 **Служба снова работает** — с длительностью простоя.

## Настройка (`.env`)

Скопируйте `.env.example` в `.env`:

| Параметр | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `TELEGRAM_ADMIN_ID` | Telegram ID админа (@userinfobot); несколько — через запятую |
| `SERVER_NAME` | название сервера в сообщениях |
| `TARGET_HOST` | какой сервер проверять (имя или IP); пусто — этот же компьютер |
| `CHECK_INTERVAL_SEC` | интервал проверки, сек (по умолчанию 30) |
| `TELEGRAM_PROXY_URL` | прокси, если нужен |

Список служб хранится в `data/services.json` и меняется командами бота.
Если при первом запуске есть старый `config/config.json`, службы из него переносятся автоматически.

**Один токен — один запущенный бот.** Если тот же бот запущен где-то ещё, Telegram выдаёт ошибку 409
и команды работают нестабильно.

## Проверка другого сервера по сети

Бот можно запустить на одном сервере (с интернетом), а проверять службы на другом — например,
на сервере QUIK без выхода в интернет. На сервер QUIK при этом ничего ставить не нужно.

1. В `.env` укажите `TARGET_HOST=172.23.10.82`.
2. Учётная запись, под которой работает бот, должна быть **администратором на сервере QUIK**,
   иначе Windows ответит «Отказано в доступе»:
   - в домене — запустите бота под доменной учётной записью с правами администратора на сервере QUIK;
   - без домена — сохраните логин и пароль администратора сервера QUIK (от имени того же пользователя, под которым работает бот):
     ```powershell
     cmdkey /add:172.23.10.82 /user:172.23.10.82\Administrator /pass
     ```
3. Проверьте вручную: `sc.exe \\172.23.10.82 query QuikServerQ` должна показать `STATE`.
4. Сеть: с сервера бота до сервера QUIK должен быть открыт доступ к службам Windows
   (порт 445 / RPC, правило брандмауэра «Удалённое управление службами»).

Если сервер QUIK перестаёт отвечать, придёт одно сообщение «🔴 Сервер недоступен», а не по каждой службе.

## Запуск

```powershell
npm install
npm run build
npm start              # или через pm2: pm2 start dist/index.js --name quik-monitor
npm run check-once     # однократная проверка служб без Telegram
npm test
```

Нужен Node.js ≥ 22.13.

## Установка службой Windows на сервере

1. На ПК разработчика: `.\scripts\build-release.ps1 -NodeZip <node-v22-win-x64.zip> -WinSWExe <WinSW-x64.exe>`.
2. На сервере распакуйте архив (например, в `C:\QuikMonitor\`) и создайте `.env`.
3. От администратора: `.\scripts\install-service.ps1 -Start`.
4. В Telegram придёт «🔵 Мониторинг запущен». Добавьте службы через `/find` и `/add`.

| Действие | Команда |
|---|---|
| Статус | `Get-Service QuikMonitor` |
| Перезапуск | `Restart-Service QuikMonitor` |
| Удаление | `.\scripts\uninstall-service.ps1` |
| Логи | `logs\monitor.*.log` |
